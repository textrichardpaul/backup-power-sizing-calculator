# Calculator v1.1 notes

Prepared 2026-11-04 from one read of the live demo at
textrichardpaul.github.io/backup-power-sizing-calculator, checked against the
live index.html in this repo (the served file and the repo file match). The
test suite passes as is (npm test, all cases green). The defects below are
real behaviour in the current code, listed in fix order. No new features are
proposed here.

## Defects

1. The runtime table usually cannot show the recommended size.
   The recommendation uses nine capacity classes (300, 500, 1,000, 1,500,
   2,000, 3,600, 5,000, 7,200, 10,000 Wh), but the runtime table only lists
   four (500, 1,000, 2,000, 3,600 Wh). When the recommended class is not one
   of those four, no row is marked "(your size)" and no row is highlighted.
   This hits built-in presets, not just edge cases: "Sleep with CPAP"
   recommends the 1,500 Wh class, "Keep the basement dry" recommends
   5,000 Wh, and "Full day without power" recommends 7,200 Wh. None of those
   sizes appears in the runtime table.

2. Edited fields can show a different value from the one being calculated.
   Typing a run share above 100, a negative number, or a fractional quantity
   is silently corrected in the calculation (capped, floored, or rounded),
   but the field on screen keeps showing what was typed. A visitor can be
   looking at "150 percent" or "1.5" while the answer is based on 100
   percent or 2.

3. The custom backup length field can disagree with the result.
   The field accepts values above the stated 240 hour maximum. The
   calculation clamps to 240, but the field keeps showing the typed value,
   while the results line quotes the clamped length. Clearing the field or
   typing 0 leaves the previous length in force with no sign that the entry
   was ignored.

4. "Hours a day" accepts values above 24.
   There is no upper check on that field. A value such as 100 hours a day is
   accepted and inflates the energy total (for backups longer than 24 hours
   it is scaled up further), instead of being capped at 24 or flagged.

5. The space heater verdict ignores the heater's own settings.
   The verdict quotes how long the recommended station runs the heater on
   its own, worked out from watts and quantity only. If a visitor lowers the
   heater's run share or hours, the sizing result changes but the verdict
   figure does not, so the two can contradict each other.

6. Opening or closing a device's Details drops keyboard focus.
   Toggling Details (or removing a device) rebuilds the whole device list,
   so the control that was just used disappears and focus falls back to the
   page body. Keyboard and screen reader users lose their place on every
   toggle.

## Observation, not counted as a defect above

With scripts off or blocked, the demo shows no scenario or room presets, an
empty device list, and a 0 Wh answer, because all content is built by
script. A short no-script note would at least explain why the page looks
empty in that state.
